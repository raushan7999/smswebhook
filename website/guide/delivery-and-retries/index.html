Delivery, retries and offline

How messages are delivered, retried and kept safe without internet.

What happens to each SMS

  1. The SMS is saved on the phone. Duplicate broadcasts of the same SMS are ignored.
  2. Every enabled webhook checks its rules. Matches are queued; the rest are marked Filtered for that webhook.
  3. Each queued delivery is sent as soon as there is internet (or Wi-Fi, if you chose Only on Wi-Fi).
  4. A 2xx response marks it Sent. Otherwise the app retries or marks it Failed.

Statuses

StatusMeaning
PendingWaiting to be sent (for example, no internet yet)
SendingThe request is in progress
RetryingA temporary problem; another attempt is scheduled
Delivered / SentYour server answered with 2xx
FailedA permanent error, or retries ran out. Tap Retry after fixing the cause
FilteredThe message didn't match this webhook's rules

Retries

  • Timeouts, connection errors and HTTP 408, 425, 429 and 5xx are retried. Other 4xx responses and certificate errors are not, because repeating the same request can't succeed.
  • The wait doubles after each failure: with a 30 s first delay, 30 s → 1 min → 2 min → 4 min…
  • Maximum retries is the number of retries after the first attempt.
  • A Retry button appears on failed deliveries; Retry failed on the webhook detail screen re-queues them all.

Offline and restarts

Deliveries wait for a connection and don't use up retries while the phone is offline. They also survive the app being closed and the phone restarting.

Duplicates

Each message is sent to each webhook once. If your server accepted a request but its reply never reached the phone, the app retries; use the X-Idempotency-Key header to ignore the repeat. See Receive webhooks on your server.
