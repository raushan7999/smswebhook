Add a webhook

Walk through the seven-step webhook editor and test your endpoint.

Open Webhooks and tap Add webhook. The editor has seven steps; Next checks each step and shows any problem next to the field.

  1. Webhook: a Webhook name (for example Payment Server) and the Webhook URL. The URL must start with https://. Requests are sent with POST.
  2. Headers & authentication: add a Bearer token, Basic auth, an API key header or any custom header. See Headers and authentication.
  3. Message filters: All messages, or Only matching messages with your rules. See Message filters.
  4. Payload: JSON, a custom JSON template, raw text or form data. See Payload formats.
  5. Regex extraction (optional): named values such as amount. See Extract values with regex.
  6. Retry & timeout: Timeout (seconds), Maximum retries and First retry delay (seconds). The defaults (15 s, 5 retries, 30 s) suit most servers.
  7. Review: check the summary, use Edit to jump back to any step, leave Enable webhook on, tap Send test request, then Save webhook.

Test your webhook

Test (on the webhook card, the detail screen or the Review step) sends a sample SMS with your real headers and format. The result shows success or failure, the HTTP status, the response time, the request body and your server's response. Tests aren't saved as deliveries, and the request carries X-SmsWebhook-Test: true.

No server yet? Use a free request inspector such as webhook.site: paste its HTTPS URL as the webhook URL and tap Test to see exactly what arrives.

Manage webhooks

  • The switch on each card enables or disables the webhook.
  • ⋮ → Duplicate copies a webhook. The copy starts disabled, so nothing is sent twice by surprise.
  • ⋮ → Delete removes the webhook and its delivery history.
  • Tap a card to open its detail screen: full configuration, counters, Retry failed and the delivery history.
