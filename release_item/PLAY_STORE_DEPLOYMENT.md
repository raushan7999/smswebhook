## Release checklist (1.0.0)

### A. Before Play Console
- [x] Upload key created; signed `.aab`/`.apk` built, verified and tested (`2_release_v1.0.0/build_info.txt`).
- [ ] **Back up `1_signing_key/`** to two safe places and store the passwords in a password manager.
- [ ] **Uninstall the old "BC SMS Webhook" (v2.0.0, versionCode 3) from test phones** — same package name, different
      key; Android will refuse to install over it.
- [ ] **One real end-to-end test:** install the release APK, add a webhook pointing to https://webhook.site/…,
      send an SMS from another phone, confirm it arrives and shows **Delivered** (`docs/12-testing.md` §4).
- [ ] Create the mailbox / alias **smswebhook@bestcallerapp.com** (used in the listing, website and app).
- [ ] **Publish the website**: push `website/` to GitHub Pages (or any static host); DNS
      `CNAME smswebhook → <github-user>.github.io`; enable HTTPS. Check https://smswebhook.bestcallerapp.com/privacy/ loads.
- [ ] Have the privacy policy and terms reviewed (DPDP Act 2023); confirm the grievance-officer details.

### B. Create the app
- [ ] Play Console → Create app (`5_play_console_forms` §1). Free, App, en-IN.

### C. App content (Policy → App content) — answers in `5_play_console_forms/PLAY_CONSOLE_FORMS.md`
- [ ] Privacy policy · App access · Ads (**No**) · Content rating · Target audience (18+) · Data safety (§9) · Advertising ID (**No**)
- [ ] Government / Financial / Health / News: **No** · Account deletion: not applicable
- [ ] **Sensitive permissions → SMS and Call Log declaration (§13)**: core functionality, description and a
      30–60 s demo video (record it on a phone: permission → add webhook → SMS arrives at webhook.site).
- [ ] Store settings: Tools, smswebhook@bestcallerapp.com, website https://smswebhook.bestcallerapp.com/
- [ ] Main store listing: paste `3_store_listing/store_listing_en-IN.txt`; upload `4_graphics/app-icon-512.png`,
      `feature-graphic-1024x500.png`, `store/phone_v1.0.0/` (8), `store/tablet-7in_v1.0.0/`, `store/tablet-10in_v1.0.0/`;
      YouTube URL of the promo video (`6_promo_video_v1.0.0/README.txt`). Optional: Hindi translation.

### D. Play App Signing + first upload
- [ ] Test and release → **Internal testing** → Create release → upload the `.aab`. Accept **Play App Signing**.
- [ ] Release name `1.0.0 (10000)`, paste `2_release_v1.0.0/release_notes.txt`, roll out to internal testers.
- [ ] Record the **app-signing certificate SHA-1/SHA-256** (Play Console → App integrity) in `about_app.txt`.
- [ ] Install from the internal test link; repeat the end-to-end SMS test.

### E. Closed test → production
- [ ] New personal accounts: **closed test with ≥ 12 testers for 14 continuous days** (testers need SMS-capable phones).
- [ ] Apply for production; Production → Create release → same `.aab` → staged rollout (20 % → 100 %).

### F. After launch
- [ ] Share `teaser-vertical-1080x1920.mp4` (Shorts / Reels / Status) with the Play link.
- [ ] Watch Android vitals (crashes / ANRs) for the first week.

### If the SMS declaration is refused
- Offer the signed APK for direct download on the website (add a download section linking `sms-webhook-v<ver>-release.apk`
  with its SHA-256), and explain "Allow restricted settings" (Android 13+) in the guide — already covered in
  `website/guide/getting-started/`.

## Next version (e.g. 1.0.1) — routine
1. Bump `appVersion` in `app/build.gradle.kts` (1.0.1 → versionCode 10001). Never reuse a versionCode.
2. `./gradlew :app:clean :app:testDebugUnitTest :app:lintRelease :app:bundleRelease :app:assembleRelease`.
3. New folder `2_release_v1.0.1/` with `.aab`, `.apk`, `mapping.txt`, `build_info.txt` (checksums, `apksigner verify
   --print-certs`, `zipalign -c -P 16 4`), `release_notes.txt`. Leave older folders untouched.
4. If screens changed: new raw shots → `4_graphics/screenshots_v1.0.1/` (see `4_graphics/README.txt`), then
   `python3 tools/make_store_images.py v1.0.1`, `make_feature_graphic.py`, `make_teaser.py … vertical|landscape`,
   `make_audio.py`, `make_youtube_thumbnail.py`, `make_website.py`.
5. If a permission, SDK or data flow changed: update the privacy policy (in `tools/make_website.py`),
   `PLAY_CONSOLE_FORMS.md` and `docs/11-security-and-privacy.md` **before** uploading.
6. Update `docs/CHANGELOG.md`, upload, roll out.
